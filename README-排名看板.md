# CANNJudge 排名看板（GitHub Pages）

- 默认查询 `d0uB4o`。在「查询队伍」输入队名片段后选择匹配队伍，或在唯一匹配时按 Enter；`/` 聚焦搜索框。
- 顶栏可切换深色与浅色，浏览器会记住偏好。题目难度使用 CANNJudge 的 1–3 级，依次显示为简单、中等、困难。
- 总榜的「较 5 小时前」以当前榜单时间为准，选用 5 小时前或更早、距离目标至多 30 分钟的最近快照。总榜底部显示基准时间，没有基准或队伍当时未上榜时显示 `–`。
- 近 24 小时面板跟踪当前总榜前十名，展开单元格可查看每道题的采样时间、得分和排名变化。历史按队伍名称关联，队伍改名会以新名称开始积累记录。
- 「历史峰值回放」保留查询队伍的当前提交，其余队伍按题选用公开观测到的较高分，按易、中、难的系数 1、2、3 加权，再分配各题第一名的 10、20、30 分奖励。基础分显示并列时保留可用的当前第一名，否则按提交时间估算奖励归属。
- 「已观测回退」要求有更早的通过提交且基础分至少高 5 分。该标记仅说明换提交后观测到分数下降。单题反超门槛假设对手只补一道未观察到通过的题，并保留回放中的其他基础分。
- 回放使用内置的 2026-11-10 公开快照峰值，后续样本由各浏览器采集并保存在本地。不同浏览器的结果可能有差异。可以用 `node scripts/build_score_peaks.mjs docs/score-peaks.json <公开快照文件>` 更新内置峰值。

## 在线部署

1. 按 [Worker 部署说明](worker/README.md) 配置并部署 Worker，在 `docs/config.js` 填写其地址。
2. 在 GitHub 仓库 **Settings → Pages** 将 Source 设为 **GitHub Actions**。将 `COLLECTOR_SECRET` 配为仓库的 Actions secret，值与 Worker 的同名 secret 相同。
3. 合并代码到 `main`，然后在 **Actions → Rankings snapshot & Pages → Run workflow** 手动触发一次，发布静态页面并写入首个历史快照。

输入页面口令后每分钟读取榜单。Actions 约每 5 分钟采样一次，调度延迟会缩短可见的历史覆盖。历史从首次采样开始，采样之间短暂发生的变化可能不会出现在记录里。实时接口失败时，页面使用 Worker 保存的最近一次完整快照。

页面口令由浏览器验证，当前标签页刷新时会保留解锁状态。口令可以在 `docs/app.js` 中看到，榜单接口仍可直接读取。历史采样上传需要单独的采集密钥。

## 本地运行

```powershell
python -m pip install requests
python monitor/app.py   # http://127.0.0.1:8765/
```

Python 本地服务只绑定回环地址，可预览榜单和队伍查询。在线定时历史由 Worker 提供。
