# CANNJudge 排名看板（GitHub Pages）

- 默认查询 `d0uB4o`。在「查询队伍」输入队名片段后选择匹配队伍，或在唯一匹配时按 Enter；`/` 聚焦搜索框。
- 顶栏可切换深色与浅色，浏览器会记住偏好。题目难度使用 CANNJudge 的 1–3 级，依次显示为简单、中等、困难。
- 总榜的「较 5 小时前」使用 GitHub Actions 保留的总榜采样，选用距离 5 小时目标时间最近、且偏差不超过 30 分钟的快照。总榜底部显示基准时间，没有基准或队伍当时未上榜时显示 `–`。
- 近 24 小时面板跟踪当前总榜前十名，展开单元格可查看每道题的采样时间、得分和排名变化。历史按队伍名称关联，队伍改名会以新名称开始积累记录。
- 「历史峰值回放」对所有队伍按题选用公开观测到的较高分，按易、中、难的系数 1、2、3 加权，再分配各题第一名的 10、20、30 分奖励。基础分显示并列时保留可用的当前第一名，否则按提交时间估算奖励归属。
- 总览显示当前查询队伍最近 10 次观测到的新提交，以及各题最近一次提交的名次和基础分变化。区间总分与总名次变化包含同一采样区间内的其他变动。每题目标是全部队伍公开观测到的最高基础分。
- 「已观测回退」要求有更早的通过提交且基础分至少高 5 分。该标记仅说明换提交后观测到分数下降。单题反超门槛假设对手只补一道未观察到通过的题，并保留回放中的其他基础分。
- 回放包含内置公开快照峰值和 GitHub Actions 约每 10 分钟发布的共享样本，页面会显示「共享采样截至」时间。打开页面期间浏览器也会采集样本并保存在本地。

## 在线部署

1. 按 [Worker 部署说明](worker/README.md) 配置并部署 Worker，在 `docs/config.js` 填写其地址。
2. 在 GitHub 仓库 **Settings → Pages** 将 Source 设为 **GitHub Actions**。若需要 Worker 的 24 小时逐题历史，将 `COLLECTOR_SECRET` 配为仓库的 Actions secret，值与 Worker 的同名 secret 相同。
3. 合并代码到 `main`，然后在 **Actions → Rankings snapshot & Pages → Run workflow** 手动触发一次，发布静态页面并写入首个共享快照。

输入页面口令后每分钟读取榜单。Actions 在每小时的 02、12、22、32、42、52 分触发共享采样，即使页面关闭也会运行。实际采样和发布时间取决于 GitHub 排队。采样之间短暂发生的变化可能漏记。实时接口失败时，页面使用 Worker 保存的最近一次完整快照。

页面口令由浏览器验证，当前标签页刷新时会保留解锁状态。口令可以在 `docs/app.js` 中看到，榜单接口仍可直接读取。历史采样上传需要单独的采集密钥。

## 本地运行

```powershell
python -m pip install requests
python monitor/app.py   # http://127.0.0.1:8765/
```

Python 本地服务只绑定回环地址，可预览榜单和队伍查询。在线定时历史由 Worker 提供。
